## The World is Sequential

Look around you. So much of the data we interact with has an inherent **order**:

- **Text**: "The cat sat on the mat" — the meaning depends on word order
- **Speech**: Sound waves unfold over time; "recognize speech" and "wreck a nice beach" are acoustically similar
- **Time series**: Stock prices, sensor readings, weather data — past values inform future predictions
- **Music**: A melody is defined not just by which notes are played, but *when*
- **DNA**: The sequence ATCG encodes biological instructions
- **Video**: A sequence of frames where temporal context matters

The key property of all these domains is that **order matters**. "Dog bites man" is very different from "Man bites dog." Any architecture that processes sequential data must somehow respect and leverage this temporal structure.

### Why Feedforward Networks Fail

Standard feedforward neural networks (FFNNs) — the basic multi-layer perceptrons — process each input independently. They take a fixed-size input vector, transform it through layers, and produce an output. There's no concept of *time*, *order*, or *memory*.

If you tried to process a sentence word-by-word with a feedforward network, each word would be processed in complete isolation. When the network sees "mat", it has no idea that "cat" appeared three words ago. It's like having amnesia — every moment is a fresh start.

<NetworkComparison />

This is the fundamental limitation: **feedforward networks have no memory**. They can't handle variable-length sequences, they can't capture temporal dependencies, and they can't generalize across sequence positions. We need something fundamentally different.

## Enter the RNN

The core idea of a Recurrent Neural Network is beautifully simple: **give the network a hidden state that persists across timesteps**. At each moment in time, the network receives:

1. The current input `x_t`
2. The previous hidden state `h_{t-1}` (the "memory")

And it produces:
1. A new hidden state `h_t` (updated memory)
2. An output `y_t`

The hidden state acts as a compressed summary of everything the network has seen so far. It's like reading a book and keeping a running mental summary — you don't remember every word, but you retain the key information needed to understand what comes next.

### The Forward Pass Equations

At each timestep `t`, the vanilla RNN computes:

```
h_t = tanh(W_xh · x_t + W_hh · h_{t-1} + b_h)
y_t = W_hy · h_t + b_y
```

Where:
- **W_xh** — weight matrix from input to hidden state
- **W_hh** — recurrent weight matrix (hidden to hidden)
- **W_hy** — weight matrix from hidden state to output
- **b_h, b_y** — bias terms
- **tanh** — the hyperbolic tangent activation function (squashes values to [-1, 1])

The critical insight is **parameter sharing**: the same weights `W_xh`, `W_hh`, and `W_hy` are used at every timestep. This is what allows RNNs to handle sequences of any length — the network doesn't need a separate set of parameters for position 1 vs position 100.

### A Simple RNN in NumPy

Let's see what an RNN looks like in practice. Here's a minimal implementation:

```python
import numpy as np

class VanillaRNN:
    def __init__(self, input_size, hidden_size, output_size):
        # Initialize weights with small random values
        self.W_xh = np.random.randn(hidden_size, input_size) * 0.01
        self.W_hh = np.random.randn(hidden_size, hidden_size) * 0.01
        self.W_hy = np.random.randn(output_size, hidden_size) * 0.01
        self.b_h = np.zeros((hidden_size, 1))
        self.b_y = np.zeros((output_size, 1))

    def forward(self, inputs, h_prev):
        """
        inputs: list of input vectors, one per timestep
        h_prev: initial hidden state
        """
        h = h_prev
        outputs = []
        hidden_states = [h]

        for x_t in inputs:
            # The core RNN computation
            h = np.tanh(self.W_xh @ x_t + self.W_hh @ h + self.b_h)
            y_t = self.W_hy @ h + self.b_y

            hidden_states.append(h)
            outputs.append(y_t)

        return outputs, hidden_states
```

Just three matrix multiplications, a `tanh`, and a loop — that's all an RNN is. The elegance is in the recurrence: `h` carries information forward through the entire sequence.

## Unrolling Through Time

To understand how RNNs learn, we need to think about **Backpropagation Through Time (BPTT)**. The trick is to "unroll" the RNN — conceptually copy the network once for each timestep and connect them sequentially. This transforms the recurrent network into a very deep feedforward network, where the depth equals the sequence length.

<RNNUnrolled />

### How BPTT Works

1. **Forward pass**: Process the entire sequence, computing `h_t` and `y_t` at each timestep
2. **Compute loss**: Sum the losses at each timestep: `L = Σ L_t`
3. **Backward pass**: Propagate gradients backward through the unrolled network

The gradient of the loss with respect to the recurrent weights involves a chain of multiplications:

```
∂L/∂W_hh = Σ_t  ∂L_t/∂h_t · ∂h_t/∂W_hh
```

where `∂h_t/∂h_k` for some earlier timestep `k` requires multiplying through all intermediate Jacobians:

```
∂h_t/∂h_k = Π_{i=k+1}^{t}  ∂h_i/∂h_{i-1}
```

Each factor `∂h_i/∂h_{i-1} = W_hh^T · diag(tanh'(z_{i-1}))` involves the same weight matrix `W_hh`. This product of matrices is where the trouble begins.

Switch to **Backward Pass** mode in the visualization above and watch the gradients flow. Notice how they must traverse every recurrent connection — and at each step, they get multiplied by `W_hh`. This is like repeatedly photocopying a photocopy: the signal degrades (or explodes) with each copy.

## The Vanishing Gradient Problem

This is the fundamental challenge that plagued RNNs for years and motivated the invention of LSTM. The mathematical root cause is elegant and devastating.

### The Mathematics

The gradient `∂h_t/∂h_k` is a product of Jacobian matrices:

```
∂h_t/∂h_k = Π_{i=k+1}^{t} W_hh^T · diag(σ'(z_{i-1}))
```

The spectral analysis by [Pascanu et al. (2013)](https://arxiv.org/abs/1211.5063) showed that the behavior of this product depends on the **eigenvalues of W_hh**:

- If the largest eigenvalue `λ₁ < 1/γ` (where `γ` bounds the activation derivative) → gradients **vanish exponentially**
- If the largest eigenvalue `λ₁ > 1/γ` → gradients **explode exponentially**

For the tanh activation, `γ = 1` (since max |tanh'(x)| = 1). So if the eigenvalues of W_hh are less than 1, gradients decay exponentially with the distance in time. After just 10-20 timesteps, the gradient from the loss to the early inputs becomes negligibly small.

<GradientExplorer />

### What This Means in Practice

**Vanishing gradients** mean the network cannot learn long-range dependencies. If a word at position 3 is critical for predicting a word at position 50, the gradient signal from position 50 simply cannot reach position 3 — it decays to zero long before arriving.

Consider the sentence: *"The **cat**, which sat on the mat and looked out the window at the birds flying south for the winter, **was** sleepy."* — The verb "was" must agree with "cat" (singular), but they're separated by many words. A vanilla RNN would struggle to learn this dependency because the gradient from "was" back to "cat" would vanish.

**Exploding gradients** cause the opposite problem: parameter updates become enormous, leading to NaN losses and training instability. This is easier to fix — you can simply **clip the gradient norm**:

```python
def clip_gradients(gradients, max_norm=5.0):
    """Rescale gradients if their norm exceeds the threshold"""
    total_norm = np.sqrt(sum(np.sum(g**2) for g in gradients))
    if total_norm > max_norm:
        scale = max_norm / total_norm
        gradients = [g * scale for g in gradients]
    return gradients
```

But gradient clipping doesn't help with vanishing gradients. For that, we need a fundamentally different architecture — one that creates a "highway" for gradients to flow through time without decay.

### A Dynamical Systems Perspective

There's a beautiful connection to dynamical systems theory. The hidden state sequence `h_1, h_2, h_3, ...` can be viewed as a dynamical system:

- **Vanishing gradients** ↔ The system rapidly converges to an attractor. Small perturbations to early states have no effect on later states — the system "forgets."
- **Exploding gradients** ↔ The system is near a bifurcation boundary. Tiny perturbations cause massive divergence — the system is chaotically sensitive.

The ideal operating regime is at the **edge of chaos** — where the system is sensitive enough to retain information but stable enough to not diverge. This is extremely difficult to achieve with vanilla RNNs, which is why gated architectures became necessary.

## LSTM: Long Short-Term Memory

The Long Short-Term Memory network, proposed by [Hochreiter & Schmidhuber (1997)](https://www.bioinf.jku.at/publications/older/2604.pdf) and refined over the years, is one of the most important innovations in deep learning. Its key insight is strikingly simple: **use addition instead of multiplication to propagate state through time**.

### The Core Innovation: The Cell State

An LSTM introduces a separate **cell state** `c_t` — a "memory highway" that runs across all timesteps with **additive updates**. Instead of multiplying through weight matrices (like the hidden state in vanilla RNNs), the cell state is updated via:

```
c_t = f_t ⊙ c_{t-1} + i_t ⊙ c̃_t
```

This is addition — not matrix multiplication. The gradient of `c_t` with respect to `c_{t-1}` is simply `f_t` (the forget gate), which is a sigmoid value that can be close to 1. This means **gradients can flow unchanged through the cell state** across arbitrarily many timesteps. Hochreiter called this the **Constant Error Carousel**.

### The Gates

LSTM uses three gating mechanisms — each a sigmoid layer that outputs values between 0 and 1, acting as learned "valves" controlling information flow:

<LSTMViz />

#### 1. Forget Gate (f_t)

```
f_t = σ(W_f · x_t + U_f · h_{t-1} + b_f)
```

The forget gate examines the current input and previous hidden state, and outputs a vector of values between 0 and 1 for each dimension of the cell state. A value of 0 means "completely forget this," while 1 means "completely retain this."

**Intuition**: When reading a story, if a character leaves the scene, the forget gate learns to clear that character's information from the cell state to make room for new information.

#### 2. Input Gate (i_t) + Candidate Values (c̃_t)

```
i_t = σ(W_i · x_t + U_i · h_{t-1} + b_i)
c̃_t = tanh(W_c · x_t + U_c · h_{t-1} + b_c)
```

Two things happen in parallel:
- The **input gate** decides *which* dimensions to update (values near 0 or 1)
- The **candidate layer** creates new potential values to store (values in [-1, 1])

Their element-wise product `i_t ⊙ c̃_t` determines the actual update to the cell state.

#### 3. Output Gate (o_t)

```
o_t = σ(W_o · x_t + U_o · h_{t-1} + b_o)
h_t = o_t ⊙ tanh(c_t)
```

The output gate controls which parts of the cell state are exposed as the hidden state `h_t`. The cell state passes through `tanh` (squashing to [-1, 1]) and is filtered by the output gate.

**Intuition**: The cell state might store the grammatical number (singular/plural) of the subject, but the output gate only exposes this when it's needed for verb agreement.

### Why This Solves Vanishing Gradients

Let's compare the gradient flow:

| Architecture | Gradient through time | Behavior |
|---|---|---|
| **Vanilla RNN** | `∂h_t/∂h_{t-1} = W_hh · diag(tanh'(...))` | Multiplicative through W — vanishes/explodes |
| **LSTM** | `∂c_t/∂c_{t-1} = f_t` | Just the forget gate value — can be ≈ 1 |

The cell state gradient bypasses all weight matrices entirely. When the forget gate is close to 1 (which it learns to be for information that needs long-term retention), gradients pass through the cell state almost perfectly preserved. This is the **Constant Error Carousel** — the key innovation that made training deep sequential models practical.

### LSTM in PyTorch

```python
import torch
import torch.nn as nn

class LSTMModel(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_dim, output_dim):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.lstm = nn.LSTM(embed_dim, hidden_dim, batch_first=True)
        self.fc = nn.Linear(hidden_dim, output_dim)

    def forward(self, x):
        embedded = self.embedding(x)
        # LSTM returns: output (all h_t), (final h_n, final c_n)
        output, (h_n, c_n) = self.lstm(embedded)
        # Use the final hidden state for classification
        return self.fc(h_n.squeeze(0))
```

### Parameter Count

For a single LSTM layer with hidden size `h` and input size `x`:
- **4 input weight matrices**: 4 × (h × x)
- **4 recurrent weight matrices**: 4 × (h × h)
- **4 bias vectors**: 4 × h

Total: **4(hx + h² + h)** parameters — roughly 4× a vanilla RNN of the same size. The extra parameters are well worth the improved gradient flow.

## GRU: A Simpler Alternative

The Gated Recurrent Unit, introduced by [Cho et al. (2014)](https://arxiv.org/abs/1406.1078), asks a natural question: **Can we get LSTM-like performance with fewer gates?** The answer is a qualified yes.

GRU simplifies LSTM in two important ways:
1. **No separate cell state** — the hidden state does double duty
2. **Two gates instead of three** — the update gate and reset gate

<GRUViz />

### The Equations

```
z_t = σ(W_z · x_t + U_z · h_{t-1} + b_z)           # Update gate
r_t = σ(W_r · x_t + U_r · h_{t-1} + b_r)           # Reset gate
h̃_t = tanh(W_h · x_t + U_h · (r_t ⊙ h_{t-1}) + b_h)  # Candidate
h_t = (1 - z_t) ⊙ h_{t-1} + z_t ⊙ h̃_t             # Interpolation
```

### Understanding Each Gate

**The Update Gate (z_t)** combines the roles of LSTM's forget and input gates. It controls the balance between keeping old information and accepting new information. The final hidden state is a **linear interpolation** between the old state and the candidate:

```
h_t = (1 - z_t) · h_{t-1}  +  z_t · h̃_t
       └── keep old ──┘     └── use new ──┘
```

When `z_t ≈ 0`, the unit copies the previous state through unchanged (like a skip connection). When `z_t ≈ 1`, it fully replaces the state with the new candidate.

**The Reset Gate (r_t)** controls how much of the previous state is visible when computing the candidate. When `r_t ≈ 0`, the candidate is computed as if there's no history — the unit "resets" and starts fresh. This is useful when the model encounters a topic change or a new sentence.

### LSTM vs GRU: Which Should You Choose?

[Chung et al. (2014)](https://arxiv.org/abs/1412.3555) conducted extensive empirical comparisons:

- **Both vastly outperform vanilla RNNs** — gating is the key ingredient
- **No clear universal winner** — performance is task-dependent
- **GRU trains faster** due to fewer parameters (~75% of LSTM)
- **LSTM sometimes wins on complex tasks** requiring fine-grained memory control
- **GRU often matches LSTM** on simpler tasks

**Rule of thumb**: Start with GRU for prototyping (faster training, simpler). Switch to LSTM if you need the extra representational power or if GRU performance plateaus.

## Bidirectional RNNs

So far, our RNNs have been **unidirectional** — at any given position, they only have access to *past* context. But many tasks benefit from seeing the future too.

Consider named entity recognition: in "Apple released a new iPhone", knowing the words *after* "Apple" (specifically "released" and "iPhone") strongly suggests it's a company, not a fruit. A unidirectional RNN processing left-to-right wouldn't have this information when it encounters "Apple."

**Bidirectional RNNs** solve this by running two separate RNNs — one forward and one backward — and concatenating their outputs:

<BiRNNViz />

### Architecture

```
Forward:   h→_t = RNN(x_t, h→_{t-1})    # Processes left to right
Backward:  h←_t = RNN(x_t, h←_{t+1})    # Processes right to left
Output:    h_t = [h→_t ; h←_t]           # Concatenation
```

The forward and backward RNNs have **completely separate parameters**. The output at each position is the concatenation of both, giving a representation that captures **bidirectional context**.

### When to Use Bidirectional RNNs

**Use when**: You have access to the entire input sequence (classification, NER, machine translation encoding, speech recognition)

**Don't use when**: You're generating text auto-regressively (language modeling, text generation) — you can't see the future during generation!

Bidirectional LSTMs/GRUs are the workhorses of many NLP and speech tasks. The encoder in [Bahdanau et al.'s attention paper (2014)](https://arxiv.org/abs/1409.0473) uses a bidirectional GRU, producing annotations that capture both left and right context at every position.

## Sequence-to-Sequence Models

Real-world sequence problems often require mapping from one sequence to another of **different length**. Translation ("I am a student" → "Je suis étudiant"), summarization (long article → short summary), and question answering all share this structure.

The breakthrough **Sequence-to-Sequence (Seq2Seq)** architecture by [Sutskever et al. (2014)](https://arxiv.org/abs/1409.3215) introduced the **encoder-decoder** framework:

<Seq2SeqViz />

### Architecture

**Encoder**: Reads the entire input sequence and compresses it into a fixed-length **context vector** `c` — the final hidden state of the encoder LSTM.

```
h_t = LSTM_encoder(x_t, h_{t-1})
c = h_T  (final hidden state)
```

**Decoder**: Generates the output sequence token by token, conditioned on the context vector:

```
s_t = LSTM_decoder(y_{t-1}, s_{t-1})    where s_0 = c
P(y_t | y_{<t}, x) = softmax(W · s_t)
```

### Key Innovations from the Original Paper

1. **Deep LSTMs**: 4 layers with 1000 hidden units each, totaling ~384M parameters
2. **Source Reversal**: Feeding the input in reverse order ("sat cat The" instead of "The cat sat") dramatically improved BLEU scores from 25.9 to 30.6. The intuition: reversing reduces the average distance between corresponding source-target word pairs
3. **Beam Search**: At inference time, instead of greedily picking the most probable token, maintain top-k candidates (beam size 2 was sufficient)
4. **Ensemble**: 5 independently trained LSTMs, with their predictions averaged, achieved **34.81 BLEU** on WMT'14 English-to-French — surpassing phrase-based statistical MT (33.30 BLEU)

### The Bottleneck Problem

There's a fundamental limitation: the **entire source sentence** must be compressed into a single fixed-length vector `c`. For short sentences, this works reasonably well. But as sentences grow longer, important information is inevitably lost.

Sutskever et al. observed robust performance up to ~35 words, after which translation quality degraded significantly. The context vector simply cannot hold enough information. Imagine trying to remember a 50-word sentence by distilling it into a single mental snapshot — you'd lose details.

This bottleneck directly motivated the invention of the **attention mechanism**.

## Attention: The Game Changer

The attention mechanism, introduced by [Bahdanau et al. (2014)](https://arxiv.org/abs/1409.0473), is arguably the most consequential innovation in the RNN era. Instead of compressing the entire source into one vector, attention lets the decoder **dynamically look back** at all encoder states and decide what's relevant at each generation step.

### The Core Idea

At each decoder timestep `i`, attention computes a **unique context vector** `c_i` as a weighted sum of all encoder hidden states:

```
e_{ij} = a(s_{i-1}, h_j)                    # Alignment score
α_{ij} = softmax_j(e_{ij})                   # Attention weights
c_i = Σ_j α_{ij} · h_j                       # Context vector
s_i = f(s_{i-1}, y_{i-1}, c_i)              # Decoder update
```

Where:
- `s_{i-1}` is the decoder's previous hidden state
- `h_j` is the encoder's hidden state at position `j`
- `a()` is an alignment function (a small neural network)
- `α_{ij}` are the attention weights — a probability distribution over source positions

The alignment function `a()` can take several forms:

| Type | Formula | Notes |
|---|---|---|
| **Additive (Bahdanau)** | `v^T · tanh(W₁·s + W₂·h)` | Single-layer MLP, most general |
| **Multiplicative (Luong)** | `s^T · W · h` | Bilinear form, faster |
| **Dot-product** | `s^T · h` | Simplest, requires same dimensions |
| **Scaled dot-product** | `(s^T · h) / √d` | Used in Transformers |

<AttentionViz />

### Why Attention Is Revolutionary

1. **No information bottleneck**: Instead of one fixed-length vector, the decoder has access to all encoder states. A 100-word sentence gets 100 hidden states, each capturing local context

2. **No length degradation**: Bahdanau et al. showed that attention-based models maintain quality even for sentences of 50+ words, while vanilla seq2seq degrades severely

3. **Interpretability**: The attention weights `α_{ij}` form an alignment matrix that shows *which source words the model looked at* when generating each target word. This is directly interpretable

4. **Soft alignment**: Unlike traditional statistical MT which required hard word-to-word alignments, attention computes a **soft, differentiable** alignment — fully end-to-end trainable via backpropagation

5. **Handles reordering**: Languages have different word orders (e.g., "red car" in English → "voiture rouge" in French). Attention naturally handles non-monotonic alignments

### Implementation

```python
class BahdanauAttention(nn.Module):
    def __init__(self, hidden_dim):
        super().__init__()
        self.W1 = nn.Linear(hidden_dim, hidden_dim, bias=False)
        self.W2 = nn.Linear(hidden_dim, hidden_dim, bias=False)
        self.v = nn.Linear(hidden_dim, 1, bias=False)

    def forward(self, decoder_state, encoder_outputs):
        # decoder_state: (batch, hidden)
        # encoder_outputs: (batch, seq_len, hidden)

        # Alignment scores
        scores = self.v(torch.tanh(
            self.W1(decoder_state.unsqueeze(1)) +
            self.W2(encoder_outputs)
        ))  # (batch, seq_len, 1)

        # Attention weights (softmax over source positions)
        weights = torch.softmax(scores, dim=1)

        # Context vector (weighted sum of encoder outputs)
        context = (weights * encoder_outputs).sum(dim=1)

        return context, weights.squeeze(-1)
```

## The Road to Transformers

The attention mechanism proved so powerful that researchers began to ask a radical question: **What if we used attention *without* recurrence?**

RNNs process sequences token by token — inherently sequential. This means:
- **Cannot parallelize** within a sequence (each step depends on the previous)
- Training time scales linearly with sequence length
- Even with LSTM/GRU, very long-range dependencies remain challenging

In 2017, [Vaswani et al.](https://arxiv.org/abs/1706.03762) published "Attention Is All You Need," introducing the **Transformer** architecture. The key innovation was **self-attention** — where every position attends to every other position, not just decoder-to-encoder:

```
Self-Attention(Q, K, V) = softmax(Q · K^T / √d_k) · V
```

This eliminated recurrence entirely, enabling:
- **Massive parallelization** (all positions computed simultaneously)
- **O(1) path length** between any two positions (vs O(n) for RNNs)
- **Scaling to billions of parameters** (GPT, BERT, and beyond)

The evolution:
```
Vanilla RNN → LSTM/GRU → Seq2Seq → Attention + RNNs → Transformers (no RNNs!)
```

Transformers went on to power BERT, GPT, T5, and eventually the large language models we use today. But every one of these breakthroughs stands on the shoulders of the RNN innovations we've explored in this guide.

## Practical Training Tips

If you're working with RNNs (they're still valuable for small-scale, streaming, and edge deployments!), here are proven training techniques:

### Gradient Clipping

The most important technique for stable RNN training. Rescale gradients when their norm exceeds a threshold:

```python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=5.0)
```

### Weight Initialization

Use **orthogonal initialization** for recurrent weight matrices. This ensures eigenvalues start near 1, placing the network in the "healthy gradient" regime:

```python
for name, param in model.named_parameters():
    if 'weight_hh' in name:
        nn.init.orthogonal_(param)
```

### Dropout (Including Recurrent Dropout)

Standard dropout can be applied to inputs and outputs, but applying it to recurrent connections requires care. Use the same dropout mask across timesteps:

```python
# PyTorch LSTM supports dropout between layers
lstm = nn.LSTM(input_size, hidden_size, num_layers=2, dropout=0.3)
```

### Learning Rate Scheduling

Start with a reasonable learning rate (e.g., 0.001 for Adam) and decay it:

```python
scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(
    optimizer, patience=3, factor=0.5
)
```

### Teacher Forcing with Scheduled Sampling

During training, feed ground-truth tokens to the decoder (teacher forcing). During inference, use the model's own predictions. Bridge the gap with **scheduled sampling** — gradually increasing the probability of using model predictions during training.

5. **Sutskever, Vinyals & Le (2014)** — ["Sequence to Sequence Learning with Neural Networks"](https://arxiv.org/abs/1409.3215). The landmark seq2seq paper with deep LSTMs achieving state-of-the-art machine translation.

6. **Bahdanau, Cho & Bengio (2014)** — ["Neural Machine Translation by Jointly Learning to Align and Translate"](https://arxiv.org/abs/1409.0473). Introduced the attention mechanism, eliminating the information bottleneck.

7. **Greff et al. (2017)** — ["LSTM: A Search Space Odyssey"](https://arxiv.org/abs/1503.04069). Extensive empirical study of LSTM variants, finding that forget gate and output activation are the most critical components.

8. **Vaswani et al. (2017)** — ["Attention Is All You Need"](https://arxiv.org/abs/1706.03762). The Transformer paper that eliminated recurrence entirely.
